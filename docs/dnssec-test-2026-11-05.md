На dev.kislovs.ru установлен публичный релиз **v0.2.0**, исходный commit `a55113c286762e8035fe8cee51be0454c793feb0`. - `go test -race ./...` и `go vet ./...` прошли локально и в GitHub Actions. Локальная и CI интеграция используют настоящий PostgreSQL 16; SQLite проверяется тем же набором тестов.

- Проверены сохранение настроек через API, запрет неверных anchors, применение без перезапуска, явный лимит NSEC3=0, Prometheus, SQL roundtrip и защита от конфликта ревизий.
- В браузере проверены раздел DNSSEC, загрузка IANA в редактор, сохранение и сохранность лимита NSEC3=0 после обновления страницы.
- Отдельный интернет-тест `GHOLE_DNSSEC_LIVE=1 go test ./internal/core -run TestDNSSECLive -v -count=1` прошёл в forward и recursive режимах: cloudflare.com A/DNSKEY/DS, example.com A, неподписанный www.github.com, dnssec-failed.org, подписанные отрицательные ответы Cloudflare и зоны .se.
- Linux amd64 canary-бинарник с новым Go 1.27 запущен в контейнерах ALT p11 и Astra UBI 1.8: SQLite и проверка конфигурации прошли. Это дополнительный smoke-тест бинарника; ограничения проверки дистрибутивов перечислены в [compatibility.md](compatibility.md). Сборки arm64 созданы кросс-компиляцией.

## Короткий прогон проверенного кеша

Пробный экземпляр на том же сервере (3 vCPU, около 4 GiB RAM), отдельные SQLite и localhost:1153, recursive, DNSSEC включён, журнал включён. Прогрет запрос cloudflare.com A с DO. Команда: `dnsperf -s 127.0.0.1 -p 1153 -D -d queries.txt -l 5 -Q 5000 -q 200 -t 2`.

Отправлено и завершено 24 996 запросов, потерь 0, NOERROR 100%. Получено **4 999,11 запросов/с**, среднее время **1,393 мс**, максимум 46,652 мс. Счётчик secure после теста подтвердил 25 000 ответов вместе с предварительными функциональными запросами. [Исходный вывод dnsperf](../benchmarks/2026-11-05/dnssec/cached_udp_5000.txt).

Это короткая проверка стабильности при заданной скорости, а не предел производительности, p99 или измерение холодной рекурсии/криптографии. Прогретый кеш не перепроверяет криптографическую подпись на каждом запросе: он учитывает TTL цепочки и проверяет период RRSIG при чтении. Зависимость от сети и авторитетных серверов этим прогоном не измерена.

## Границы реализации

Реализована локальная валидация внешних ответов. Подписание собственных authoritative-зон и автоматическое RFC 5011 сопровождение ключей не реализованы. Root anchors обновляются администратором через проверенную HTTPS-загрузку IANA и сохранение в панели либо с обновлением программы. Требуются правильные системные часы. Набор тестов и данный прогон не заменяют независимый аудит DNSSEC/RFC compliance.
