# Доступ к gdns

Панель поддерживает локальные учётные записи, LDAP / Active Directory и существующий административный Bearer-токен.

При первом запуске версии с поддержкой пользователей создаётся локальный `admin`. Его случайный пароль записывается в файл `<config>.admin-password` с правами 0600. На dev.kislovs.ru:

```sh
ssh -t -p 22222 roman@dev.kislovs.ru 'sudo cat /var/lib/gdns/config.json.admin-password'
```

Откройте HTTPS-панель, выберите «Локальная учётная запись» и введите `admin` и пароль из файла. В разделе «Доступ и аккаунт» можно сменить пароль, создать пользователей и настроить домен. Файл содержит только первоначальный пароль: после смены он не обновляется. При последующих запусках существующая учётная запись не сбрасывается. Восстановить доступ можно существующим административным токеном из `<config>.token`.

## Роли

- Администратор: все настройки, пользователи и LDAP.
- Оператор зон: DNS-зоны, ручной список блокировки, импорт и обновление настроенных фидов. Не может менять настройки сервера, DNSSEC, адреса и ключи фидов.
- Просмотр: обзор, журнал, конфигурация без секретов фидов и экспорт зон.

Последнего активного локального администратора удалить или отключить нельзя. Локальные пароли хранятся как Argon2id-хеши в отдельной таблице SQLite/PostgreSQL. Смена пароля и отключение пользователя аннулируют его существующие сессии. Изменение локальной роли действует на следующем запросе.

## LDAP / Active Directory

Настройте через веб:

1. URL контроллера `ldaps://dc.example.org:636` либо `ldap://dc.example.org:389` с StartTLS.
2. Путь к PEM-файлу доверенного CA на сервере, если сертификат не доверен системному хранилищу.
3. Bind DN/UPN и пароль сервисной учётной записи, Base DN.
4. Фильтр пользователя, например `(sAMAccountName={username})`, и атрибут групп `memberOf`.
5. Полные DN разрешённых групп для каждой роли.

Кнопка проверки выполняет поиск пользователя и проверяет его группы сервисной учётной записью; пароль самого пользователя проверяется только при входе. Имя экранируется в LDAP-фильтре. При нескольких подходящих группах выбирается старшая роль. Учитывается прямое членство из атрибута групп; вложенные группы автоматически не раскрываются. Для AD учитывается флаг отключённой учётной записи `userAccountControl`.

Доменный вход использует отдельный bind с паролем пользователя; этот пароль не сохраняется. Сертификат LDAP-сервера обязательно проверяется, незашифрованный bind запрещён. Сервисный пароль сохраняется в базе и не возвращается браузеру: `***` при сохранении означает сохранить прежний секрет. Резервные копии базы следует защищать так же, как рабочую базу.

Локальная учётная запись имеет приоритет при совпадении имени. Группы доменной сессии перепроверяются каждые пять минут. При неудаче проверки сессия завершается. Изменение настроек LDAP аннулирует доменные сессии.

## Сессии и API

Сессии живут до восьми часов, хранятся в памяти и прекращаются при перезапуске. Cookie имеет HttpOnly и SameSite=Strict, на HTTPS также Secure. Изменяющие запросы с cookie требуют `X-CSRF-Token`; его возвращает `GET /api/auth/me`. Парольный вход разрешён только через HTTPS либо по loopback, например через SSH-туннель. Заголовкам прокси для определения адреса клиента и защищённости соединения сервер не доверяет.

Автоматизация может продолжать использовать `Authorization: Bearer <admin-token>`. Этот токен обладает правами администратора и не ограничивается ролью браузерного пользователя.
