# gdns 0.7.3 — оптимизация DNSSEC, кеша и UDP

Релиз объединяет оптимизации производительности с обновлением фидов по расписанию из v0.7.2. Автор — Кислов Роман Сергеевич. Лицензия — Apache 2.0. Статус выпуска — предварительный (pre-release), как у предыдущих версий.

## Кеш и формирование ответов

- Ключ кеша теперь хранится структурой: имя, тип запроса, DNSSEC-флаги и представление зоны. При попадании в кеш не создаётся строковый ключ; строка для singleflight формируется только при промахе. Разделение split-зон сохраняется.
- Ответы с единственной A/AAAA-записью копируются в компактный объект с собственными IP-байтами, TTL и при необходимости EDNS. Это уменьшает число выделений памяти без совместного изменения кешированных записей разными клиентами.
- Буфер упаковки обычного UDP-ответа размером 1232 байта переиспользуется через пул. Буфер возвращается после завершения записи; большие буферы не удерживаются. TSIG остаётся на штатном пути подписи библиотеки.
- Для короткого ответа с одной A/AAAA-записью используется консервативная проверка размера без обхода DNS-меток. EDNS, DNSSEC и сложные ответы проходят полную проверку усечения; флаг TC сохраняет прежнюю семантику.

## Linux UDP и воркеры

- Официальные Linux-пакеты собираются с `gdns_udp_addrport`: ReadMsgUDPAddrPort/WriteMsgUDPAddrPort и один принадлежащий запросу объект для адреса, IP-байтов и packet-info. Сохраняется правильный исходный адрес ответа при wildcard-привязке, работа IPv4/IPv6, ACL и split-зон.
- В изолированном Linux UDP echo-микротесте транспортный обмен сократился с 12 до 1 выделения памяти, с 488 до 320 B/op. Это характеристика теста транспорта, а не всего DNS-запроса.
- Для каждого UDP-сокета запрашивается приёмный буфер 1 MiB, ограничиваемый настройками ядра. Системные sysctl не меняются. Существующие воркеры SO_REUSEPORT продолжают обслуживать запросы параллельно.
- Обычная сборка исходников без тега сохраняет библиотечный транспорт. На других ОС используется прежний путь. Параллельный дополнительный UDP writer и экспериментальный кеш подписанных ответов (`gdns_dnssec_mixed`) в выпуск не включены.

## DNSSEC

- При внутренней проверке отсутствия DS проверяются необходимые NSEC/NSEC3 RRset без лишней проверки SOA, которая не используется как доказательство делегирования. Ограничение срока жизни состояния по SOA сохраняется. В отрицательных ответах клиенту SOA по-прежнему проходит проверку подписи.
- Убрано повторное глубокое копирование уже приватного сообщения при обходе ответа валидатором.
- Для обычной пары записей разных типов пропускается строковая дедупликация. Для записей одного типа остаётся общий путь.
- Сохраняются проверки DS/DNSKEY, сроков подписей, области действия signer/zone, wildcard, NSEC3 opt-out и лимитов работы. Лимит одновременной криптографической работы остаётся 32: экспериментальное снижение лимита дало тайм-ауты и отклонено.

## Измерения и ограничения

В локальных микротестах цепочки DNSSEC число выделений памяти снизилось с 93 до 69 при кешированной цепочке и с 206 до 138 при новом leaf и кешированном родителе. Это не оценка сетевого p95.

На dev в трёх контрольных сериях смешанного DNSSEC-потока 5000 запросов/с p95 относительно предыдущей экспериментальной сборки gdns снизился: 10,56 → 10,17 мс; 16,09 → 14,17 мс; 11,92 → 8,67 мс. В сумме 2 млн запросов завершились без ошибок и тайм-аутов. Эти серии сравнивают две сборки gdns, а не BIND. Предыдущие неудачные и нестабильные эксперименты также сохранены в репозитории.

Сравнение установленной сборки с BIND 9.20.30 и исходные результаты: [контроль от 18 ноября](https://github.com/rkislov/gdns/blob/v0.7.3/benchmarks/2026-11-18/deployed-vs-bind/README.md). В длинном контроле 15k QPS p95 gdns/BIND составил 11,71/10,52 мс, успешная пропускная способность — 14 997/14 871 QPS, потери — 462/11 120 из 1,5 млн запросов на сервер. В смешанном DNSSEC-потоке 5k QPS p95 — 17,40/14,45 мс, потери — 0/370 из 250 тысяч. Цель снижения p95 на 20% относительно BIND не достигнута; универсальное преимущество не заявляется. Генератор и сервер работают на одном VPS с CPU steal; измерения не заменяют независимый нагрузочный стенд и не характеризуют все рекурсивные запросы в Интернет.

## Проверки и поставка

Добавлены воспроизводимые сравнения с BIND, проверка DNSSEC у обеих реализаций, балансировка уникальных запросов по UDP-потокам, фиксация исходных портов и возобновление прерванной серии без отбрасывания завершённых результатов. CI и сборка релиза проверяют стандартную и tagged-конфигурации через race detector и go vet.

Доступны статические Linux-архивы amd64/arm64, RPM для Альт Linux и РЕД ОС, DEB для Astra Linux и SHA256SUMS. [Инструкция установки](https://github.com/rkislov/gdns/blob/v0.7.3/docs/linux-installation.md), [границы проверенной совместимости](https://github.com/rkislov/gdns/blob/v0.7.3/docs/compatibility.md). Сборки arm64 и наличие пакетов не означают подтверждённую работу во всех редакциях целевых ОС.

На dev ранее установлен бинарник оптимизаций `23a3c32` с `gdns_udp_addrport`. Публикуемые пакеты собираются из объединённого исходного дерева v0.7.3, включающего изменения фидов v0.7.2; их хеши отличаются. Сам выпуск релиза не заменяет работающую службу.
